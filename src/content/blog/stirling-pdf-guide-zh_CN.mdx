## 5 分钟部署

### 前置要求

- 一台 Linux 服务器（推荐 Ubuntu 22.04+）
- Docker 已安装

没装 Docker？一行搞定：

```bash
curl -fsSL https://get.docker.com | sh
```

### 最简部署（一行命令）

```bash
docker run -d \
  --name stirling-pdf \
  -p 8080:8080 \
  -v ./stirling-data:/configs \
  stirlingtools/stirling-pdf:latest
```

打开浏览器访问 `http://你的服务器IP:8080`，就能用了。

### Docker Compose 部署（推荐）

```bash
mkdir -p ~/stirling-pdf && cd ~/stirling-pdf
```

创建 `docker-compose.yml`：

```yaml
services:
  stirling-pdf:
    image: stirlingtools/stirling-pdf:latest
    container_name: stirling-pdf
    ports:
      - "8080:8080"
    volumes:
      # 数据持久化
      - ./stirling-data/tessdata:/usr/share/tessdata  # OCR 语言文件
      - ./stirling-data/configs:/configs              # 配置和数据库
      - ./stirling-data/logs:/logs                    # 日志
      - ./stirling-data/pipeline:/pipeline            # 自动化流水线
    environment:
      # 安全配置
      - SECURITY_ENABLELOGIN=true
      - SECURITY_INITIALLOGIN_USERNAME=admin
      - SECURITY_INITIALLOGIN_PASSWORD=ChangeMe#Strong2026  # ⚠️ 必须修改为强密码
      # 语言设置
      - SYSTEM_DEFAULTLOCALE=zh-CN
    restart: unless-stopped
```

启动：

```bash
docker compose up -d
```

第一次启动需要 1-2 分钟初始化 LibreOffice 和 OCR 引擎。等日志显示 "Started" 就能用了。

### 验证部署成功

```bash
# 检查容器状态
docker ps | grep stirling-pdf

# 检查健康接口
curl -s http://localhost:8080/api/v1/info | head -5

# 查看启动日志
docker logs stirling-pdf --tail 20
```

## 踩坑记录

### 坑 1：端口被占用

**现象**：`docker compose up -d` 后容器一直重启。

**原因**：8080 端口被其他服务占用了。

**解决**：

```bash
# 查看端口占用
sudo lsof -i :8080

# 改成其他端口
# 修改 docker-compose.yml 的 ports 部分
ports:
  - "9000:8080"
```

### 坑 2：权限问题

**现象**：容器启动后无法写入配置。

**原因**：挂载目录权限不对。

**解决**：

```bash
# 创建目录并设置权限
mkdir -p ~/stirling-pdf/stirling-data
chmod -R 755 ~/stirling-pdf/stirling-data
```

### 坑 3：OCR 功能不可用

**现象**：上传扫描件后无法识别文字。

**原因**：没有下载 OCR 语言文件。

**解决**：

```bash
# 下载中文语言包
mkdir -p ~/stirling-pdf/stirling-data/tessdata
cd ~/stirling-pdf/stirling-data/tessdata
wget https://github.com/tesseract-ocr/tessdata/raw/main/chi_sim.traineddata
wget https://github.com/tesseract-ocr/tessdata/raw/main/chi_tra.traineddata
```

重启容器后 OCR 就能识别中文了。

## 进阶用法

### 1. 自动化流水线

Stirling-PDF 支持创建自动化流水线，把多个操作串起来一键执行。

比如：每天自动把某个文件夹里的 PDF 合并、压缩、加水印。

```bash
# 创建流水线目录
mkdir -p ~/stirling-pdf/stirling-data/pipeline/watched
mkdir -p ~/stirling-pdf/stirling-data/pipeline/finished
```

把文件放到 `watched` 文件夹，Stirling-PDF 会自动处理，结果放到 `finished` 文件夹。

### 2. API 集成

Stirling-PDF 提供 REST API，可以集成到你的脚本里：

```bash
# 合并多个 PDF
curl -X POST "http://localhost:8080/api/v1/general/merge-pdfs" \
  -F "fileInput=@file1.pdf" \
  -F "fileInput=@file2.pdf" \
  -o merged.pdf

# 压缩 PDF
curl -X POST "http://localhost:8080/api/v1/general/compress-pdf" \
  -F "fileInput=@large.pdf" \
  -o compressed.pdf
```

### 3. 中文界面

如果你的团队是中文用户，可以设置默认语言：

```yaml
environment:
  - SYSTEM_DEFAULTLOCALE=zh-CN
```

## 实话实说

- **它不是 Adobe Acrobat**：没有专业的 PDF 编辑能力，不能像 Word 一样直接修改文字。
- **大文件处理慢**：100MB 以上的 PDF 压缩需要等一会儿。
- **功能太多反而懵**：50+ 功能，第一次用可能不知道从哪开始。

但免费的、私有的、不限次数的 PDF 处理——这个取舍值不值，你自己最清楚。

## FAQ

**Q：Stirling-PDF 和 PDF.js 有什么区别？**

A：PDF.js 是浏览器里查看 PDF 的库，Stirling-PDF 是处理 PDF 的工具。一个只能看，一个能合并、压缩、转换、OCR、加水印。

**Q：Stirling-PDF 需要很多内存吗？**

A：标准版需要 2GB 内存，推荐 4GB。如果内存紧张，用 ultra-lite 版本，只需要 512MB。

**Q：可以处理加密的 PDF 吗？**

A：可以。Stirling-PDF 支持解密有密码的 PDF，但需要你提供密码。

**Q：支持哪些格式转换？**

A：支持 Word、Excel、PowerPoint、图片、HTML、Markdown 等 20+ 格式与 PDF 互转。

**Q：数据会上传到哪里？**

A：所有数据都在你自己的服务器上，Stirling-PDF 不会上传任何文件到外部。
